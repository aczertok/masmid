# Instructions for AI assistants (Claude, ChatGPT/Codex, and others)

Masmid (also called Limud Path) is a Duolingo-style Orthodox Torah-learning app: Mishnah, Gemara, Chumash with Rashi, Nach and the Kitzur Shulchan Aruch, with a map, a globe, a town, avatars, badges and "learn together". It is live at https://masmid.netlify.app. The owner is not a programmer; explain results in plain words.

## How the code is laid out
- `src/app/` is the whole app, split into small files that are joined back into one page in order:
  - `page.html` – the page markup, with placeholders `/*STYLE*/` and `/*SCRIPT1*/`…`/*SCRIPT3*/`.
  - `style.css` – the main styles.
  - `1-setup/`, `2-data/`, `3-app/` – the three scripts, each split into numbered pieces (`000-…js`, `001-…js`, …). **Order matters**: pieces are concatenated by file name, top to bottom, into one script. Code in a later piece can use what earlier pieces define.
  - Files named `…-data-…js` hold lesson content (generated by the builders); everything else is app code.
- `src/shim.js` – connects the app to Firebase (sign-in, saving, learners). Bundled with esbuild.
- `src/kitzur-data.js` – the Kitzur simanim 3–221 texts and questions, loaded on demand. Generated by `builders/kzbuild.py`.
- `src/firebase-config.js` – the Firebase web settings (public identifiers, not secrets).
- `builders/` – the Python/JS scripts that produced the lesson content. Reference only; they expect source texts downloaded from Sefaria.
- `docs/` – the content standards, licensing, data rules and launch guide. **Read `docs/orthodox-content-standards.md` before changing any content.**
- `public/` and `dist/` are build output. Never edit them by hand.

## Building and checking
```bash
npm ci
npm run build        # writes public/ (the website) and dist/limud.html (the single-file version)
```
Open `public/index.html` through a local server, or `dist/limud.html` directly, to check a change. `npm test` runs the sign-in/save tests (needs the Firebase emulator).

Netlify builds and publishes the site automatically from the `main` branch (see `netlify.toml`). Every pull request gets its own preview link.

## Rules
1. **Work on a branch and open a pull request.** Don't push to `main` directly. Keep each pull request to one change and describe it in plain words.
2. **Never rename or reuse ids** (lesson ids, unit keys, badge ids, avatar items, buildings). Learners' progress is stored against them. See `docs/app-and-data.md`.
3. **Content follows `docs/orthodox-content-standards.md`:** approved editions only, Hashem's Name written ה' / אלקים, modest pictures (no women, angels or Hashem drawn), bodily or marital topics never used in questions or pictures, separate groups for men, women, boys and girls.
4. **Two languages:** English and Portuguese. New on-screen English text should get a Portuguese entry in `PT_UI` (in the `…portuguese…` / language piece of `3-app/`), or it will show in English in Portuguese mode.
5. **Don't change `src/firebase-config.js` or `firestore.rules`** unless asked; rules changes must also be published in the Firebase console.
6. Keep the app working offline and on small phone screens (390px wide).
